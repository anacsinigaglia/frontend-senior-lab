Vulnerable

Safe

el.textContent = comment                 // always text

// Need to allow bold? Sanitize with an allowlist:
DOMPurify.sanitize(html, { ALLOWED_TAGS: ['b', 'i', 'em', 'strong'] })

Senior take. React already protects you by default. The risk shows up when someone uses dangerouslySetInnerHTML, inserts HTML from a rich text editor, or builds an href from user data. In code review, look for these three things first.

Experiment · Links with user data

Is this link safe?

A profile lets the user enter their own website. If you put that value straight into the href, a javascript: URL runs when someone clicks it. Compare the naive check with the URL parser check.

Examples
Naive check: !url.startsWith('javascript:')
Parser + allowlist: new URL(url).protocol

How it renders:

See the code 
const ALLOWED_PROTOCOLS = ['http:', 'https:', 'mailto:']

function safeHref(value) {
  try {
    const url = new URL(value, window.location.origin)  // normalizes like the browser does
    return ALLOWED_PROTOCOLS.includes(url.protocol) ? url.href : null
  } catch {
    return null
  }
}

// an allowlist (what is allowed) is safer than a blocklist (what is not)

Senior take. Validate on the frontend for a good experience, but the rule that protects you lives on the backend. Anyone with DevTools open can bypass the frontend.
