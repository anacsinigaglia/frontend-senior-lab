Module · Architecture and state

Every piece of state has a right place

Most frontend architecture problems come from state in the wrong place: server data copied into a global store, a prop passed through five components that don't use it, a filter that disappears on reload. Here you see the cost of each choice.

  • Separates server from clientAPI data is a cache and belongs to React Query. useState keeps what belongs to the UI.
  • Keeps state close to where it's usedLifts state only when needed, and only up to the nearest common parent.
  • Thinks about the shared linkFilter, tab and page live in the URL.

Experiment · Who re-renders

Prop drilling, Context or store

App holds the theme and the logged-in user. Three components deep in the tree use that data. Change the theme or the user and see which components re-render with each approach.

Approach
–rendered now
–unnecessary

    See the code for the three approaches 
    // Props: every layer receives and passes along, even without using it
<Layout theme={theme} user={user}> → <Sidebar theme={theme}> → <Menu theme={theme}> → <ThemeToggle theme={theme} />

// Context: no more passing, but every consumer renders when ANY field changes
const AppCtx = createContext()
<AppCtx.Provider value={{ theme, user }}>...
const { user } = useContext(AppCtx)   // UserBadge renders when the theme changes

// Store with selector (Zustand): each component subscribes only to what it reads
const useApp = create(set => ({ theme: 'light', user: 'Ana', toggleTheme: () => set(...) }))
const user = useApp(s => s.user)   // ignores theme changes

    Senior take. Passing a prop through two or three layers is normal and easy to trace. Context works well for values that rarely change (theme, user, language). A store with selectors pays off when many components read different parts of state that changes often.

      Senior take. Server data isn't application state. It's a copy that may be stale. A caching library handles deduplication, revalidation, cancellation and retry. Copying the response into Redux or Context is rebuilding that library, with bugs.
