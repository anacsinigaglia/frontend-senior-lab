Module · Quality and testing

Code that keeps the bug from happening

Quality isn't 100% coverage. It's writing types that won't let you build an invalid state, and tests that break when behavior breaks, and only then.

  • Models states with typesUses a status union instead of three booleans that can contradict each other.
  • Tests what the user seesQueries by text and role, not by CSS class or internal variable.
  • Remembers the forgotten statesLoading, error and empty are screens, not details.

Experiment · Impossible states

Three booleans or one status?

On the left, the screen is driven by isLoading, isError and data, which can be turned on in any combination. On the right, a single status only allows valid states. Toggle the flags and look for combinations that make no sense.

Three booleans: 2³ = 8 combinations

One status: 4 states, all valid

You can't build a contradictory screen.And TypeScript only lets you read data inside the success case.

Allows impossible states

type State = {
  isLoading: boolean
  isError: boolean
  data?: Contract[]
}
// { isLoading: true, isError: true, data: [...] } compiles

Discriminated union

type State =
  | { status: 'loading' }
  | { status: 'error'; error: string }
  | { status: 'empty' }
  | { status: 'success'; data: Contract[] }

switch (state.status) {
  case 'success': return <List items={state.data} />  // data only exists here
  ...
}

Senior take. React Query already returns status as a union. The point is to bring the same idea to your own types: a wizard step, a contract's status, a user permission. If two fields can't be true at the same time, the type should prevent it.

Which test breaks in a refactor?

A bag counter has three versions: the original, a refactor that only changes internal code, and one with a real bug (the number doesn't update on screen). Run both suites against each version. A good test fails on the bug and passes on the refactor.
