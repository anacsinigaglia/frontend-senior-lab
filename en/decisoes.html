Module · Technical decisions and leadership

The best choice depends on context

What sets a senior apart is explaining why they picked an option and what they are giving up. Here you weigh alternatives against explicit criteria, record the decision for the team and practice code review.

  • States the criteriaSays "I chose X because the team is small", not "X is better".
  • Leaves a recordWhoever joins a year from now understands the why without having to ask.
  • Reviews to teachSeparates what blocks the merge from personal preference.

Experiment · Trade-off matrix

Context, Zustand or Redux Toolkit?

Scores from 1 to 5 say how well each option meets each criterion. Weights say how much each criterion matters to your project. Change the weights or pick a scenario and watch the winner change.

Senior take. The matrix does not decide for you. It shows which criteria are driving the decision. If a small weight change flips the winner, discuss the weights with the team. The discussion about tools comes after.

Experiment · ADR

Record the decision in one minute

An ADR (Architecture Decision Record) is a short note in the repository: context, decision, alternatives and consequences. The fields come prefilled with the matrix result. Edit them and copy the Markdown.

Senior take. Do not delete an old ADR when the decision changes. Mark it "Superseded" and point to the new one. The history of why we changed also has value.

    


    

      

        
Experiment · Code review

        
Classify the comments on this PR

        
Four people reviewed the function below. For each comment, say whether it should block the merge, is a suggestion, is a nit or needs rewriting.

      


// utils/price.ts
export function averagePrice(prices: number[]) {
  let total = 0
  for (let i = 0; i <= prices.length; i++) total += prices[i]
  return total / prices.length
}

      

      
Senior take. Labeling the comment's intent ("blocking:", "suggestion:", "nit:") keeps the author from treating everything as mandatory. And a comment about the code should never be about the person.
