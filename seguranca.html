Módulo · Segurança

Todo dado que vem de fora é suspeito

No front, a maior parte dos ataques entra por um lugar: texto do usuário sendo tratado como código. Aqui você injeta um script de verdade, vê o que ele consegue roubar e decide onde guardar a autenticação.

  • Nunca confia em entradaComentário, parâmetro de URL e resposta de API são dados, nunca HTML.
  • Pensa como atacantePergunta o que um script injetado conseguiria ler e fazer.
  • Usa camadasEscapar, sanitizar, CSP e cookies httpOnly: uma camada cobre a falha da outra.

Experimento · XSS

Publique um comentário malicioso

Um comentário de cliente é exibido na tela. Escolha o conteúdo e a forma de exibir. Com innerHTML, o navegador interpreta o texto como HTML, e um atributo onerror vira código executado.

O DOM que o navegador montou

Vulnerável

el.innerHTML = comentario                // interpreta HTML

<div dangerouslySetInnerHTML={{ __html: comentario }} />  // React: o nome avisa

Seguro

el.textContent = comentario              // sempre texto

<p>{comentario}</p>                     // React escapa por padrão

// Precisa aceitar negrito? Sanitize com allowlist:
DOMPurify.sanitize(html, { ALLOWED_TAGS: ['b', 'i', 'em', 'strong'] })

Leitura de sênior. O React já protege você por padrão. O risco aparece quando alguém usa dangerouslySetInnerHTML, insere HTML vindo de um editor rico ou monta um href com dado do usuário. Num code review, procure essas três coisas primeiro.

Experimento · Links com dado do usuário

Esse link é seguro?

Um perfil deixa a pessoa informar o próprio site. Se você coloca esse valor direto no href, um javascript: roda quando alguém clica. Compare a checagem ingênua com a checagem pelo parser de URL.

Exemplos
Checagem ingênua: !url.startsWith('javascript:')
Parser + allowlist: new URL(url).protocol

Como fica na tela:

Ver o código 
const PROTOCOLOS_OK = ['http:', 'https:', 'mailto:']

function hrefSeguro(valor) {
  try {
    const url = new URL(valor, window.location.origin)  // normaliza como o navegador faz
    return PROTOCOLOS_OK.includes(url.protocol) ? url.href : null
  } catch {
    return null
  }
}

// allowlist (o que pode) é mais seguro que blocklist (o que não pode)

Leitura de sênior. Valide no front para dar uma boa experiência, mas a regra que protege fica no backend. O front pode ser contornado por qualquer pessoa com o DevTools aberto.
