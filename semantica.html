A tag certa já resolve metade do trabalho

Um <button> já vem com foco, teclado e anúncio para leitor de tela. Uma <div> não vem com nada disso. Nos experimentos abaixo, você testa com o teclado, ouve o que um leitor de tela anunciaria e mede o contraste.

  • Escolhe a tag pelo comportamentoLink navega, botão executa uma ação. Aparência é papel do CSS.
  • Testa sem mousePercorre a tela só com Tab, Enter e Esc antes de abrir o PR.
  • Usa ARIA por últimoARIA corrige o que o HTML não expressa. Não substitui a tag certa.

O conserto da div: 4 coisas para lembrar

<div
  role="button"                // leitor de tela anuncia "botão"
  tabIndex={0}                 // entra na ordem do Tab
  onClick={salvar}
  onKeyDown={e => {            // Enter e Espaço ativam
    if (e.key === 'Enter' || e.key === ' ') {
      e.preventDefault()
      salvar()
    }
  }}
>Salvar contrato</div>
// e ainda faltam: estado disabled, foco visível, submit em form

O botão: já vem pronto

<button type="button" onClick={salvar}>
  Salvar contrato
</button>

Leitura de sênior. Se você está escrevendo role="button" e tabIndex, pare e troque por <button>. O mesmo vale para link: se a ação muda a URL, use <a href>. Assim a pessoa consegue abrir em nova aba e o botão voltar funciona.

      // Luminância relativa (WCAG 2.x)
const canal = v => (v /= 255) <= 0.03928 ? v / 12.92 : ((v + 0.055) / 1.055) ** 2.4
const lum = ([r, g, b]) => 0.2126 * canal(r) + 0.7152 * canal(g) + 0.0722 * canal(b)

const contraste = (a, b) => {
  const [claro, escuro] = [lum(a), lum(b)].sort((x, y) => y - x)
  return (claro + 0.05) / (escuro + 0.05)     // de 1:1 até 21:1
}

      Leitura de sênior. Cor nunca deve ser o único sinal. Um status "vencido" em vermelho também precisa de texto ou ícone, porque cerca de 8% dos homens têm alguma forma de daltonismo.
