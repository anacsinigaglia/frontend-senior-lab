A melhor escolha depende do contexto

O que diferencia o sênior é conseguir explicar por que escolheu uma opção e o que está abrindo mão. Aqui você pesa alternativas com critérios explícitos, registra a decisão para o time e pratica code review.

  • Explicita os critériosDiz "escolhi X porque o time é pequeno", não "X é melhor".
  • Deixa um registroQuem chegar daqui a um ano entende o porquê sem precisar perguntar.
  • Revisa para ensinarSepara o que bloqueia o merge do que é preferência pessoal.

Context, Zustand ou Redux Toolkit?

As notas de 1 a 5 dizem o quanto cada opção atende a cada critério. Os pesos dizem o quanto cada critério importa para o seu projeto. Mude os pesos ou escolha um cenário e veja a vencedora mudar.

Leitura de sênior. A matriz não decide por você. Ela mostra quais critérios estão pesando na decisão. Se uma mudança pequena de peso troca a vencedora, discuta os pesos com o time. A discussão sobre as ferramentas vem depois.

Experimento · ADR

Registre a decisão em um minuto

Um ADR (Architecture Decision Record) é uma nota curta no repositório: contexto, decisão, alternativas e consequências. Os campos já vêm preenchidos com o resultado da matriz. Edite e copie o Markdown.

docs/adr/007-gerenciamento-de-estado.md

        

      

      
Leitura de sênior. Não apague um ADR antigo quando a decisão mudar. Marque como "Substituída" e aponte para o novo. O histórico de por que mudamos também tem valor.

    


    

      

        
Experimento · Code review

        
Classifique os comentários deste PR

        
Quatro pessoas revisaram a função abaixo. Para cada comentário, diga se ele deve bloquear o merge, se é uma sugestão, se é um detalhe ou se precisa ser reescrito.

      


// utils/preco.ts
export function precoMedio(precos: number[]) {
  let total = 0
  for (let i = 0; i <= precos.length; i++) total += precos[i]
  return total / precos.length
}

      

      
Leitura de sênior. Marcar a intenção do comentário ("bloqueante:", "sugestão:", "nit:") evita que a pessoa autora trate tudo como obrigatório. E um comentário sobre o código nunca deve falar da pessoa.
